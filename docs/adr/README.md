# ADR (Architecture Decision Record)

트레이드오프가 있는 설계 결정, 또는 왜 이렇게 구현했는지 설명이 필요한 비직관적인 선택을 기록합니다.
`CLAUDE.md`의 "ADR 자동 기록" 규칙에 따라 해당 상황이 발생하면 별도 요청 없이 아래 템플릿으로 추가합니다.

## 파일 네이밍

`000N-제목.md` (번호는 4자리, 순차 증가, 제목은 kebab-case)

예: `0001-availability-status-3단계.md`

## 템플릿

```markdown
# 000N. 제목

- 상태: 제안됨 | 승인됨 | 폐기됨 | 대체됨(→ 000M)
- 날짜: YYYY-MM-DD

## 배경

어떤 문제/상황에서 이 결정이 필요했는지.

## 대안

- 대안 1: 설명, 장단점
- 대안 2: 설명, 장단점

## 결정

무엇을 선택했고 왜인지.

## 결과

이 결정으로 인한 트레이드오프, 후속 영향.
```

## 목차

(아직 등록된 ADR이 없습니다.)
